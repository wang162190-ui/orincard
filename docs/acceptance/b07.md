## T061 combined acceptance

`tests/e2e/export-restore.spec.ts` provides one cleanup-aware real-cloud run behind `ORINCARD_RUN_B07_E2E=1`. It performs these checks against the development app, Supabase, Storage, and Trigger worker:

1. Creates one fixed project revision and requests PNG ZIP, JPG ZIP, PDF, PPTX, and MP4 together.
2. Supplies a nonexistent audio asset only to make MP4 fail with the other four formats remaining ready, then submits only MP4 again without audio. It verifies that the four successful records and assets did not change.
3. Checks image signatures and ordered page counts, PDF pages, editable PPTX DrawingML text, artifact SHA-256 values, and MP4 dimensions/codec/duration with `ffprobe`.
4. Builds and uploads a private recovery ZIP with a rendered image, inspects and confirms it through the public API, and verifies new project and asset IDs.
5. Sends a 50 MiB-plus source declaration and requires `413 FILE_TOO_LARGE` before an upload authorization is created.
6. Creates a project in a second account, downloads the first account's real data package, and recursively scans the JSON for forbidden sensitive/storage fields and the foreign marker.

Run it with the development-only credentials and provider configuration:

```sh
ORINCARD_RUN_B07_E2E=1 pnpm exec playwright test tests/e2e/export-restore.spec.ts
pnpm exec vitest run tests/cloud/package-privacy.test.ts
```

The test marks its projects and artifacts deleted and removes created Storage objects in `finally`. On 2026-09-10 the uninterrupted development-cloud run completed in 4.2 minutes with `1 passed`; the independent privacy contract completed with `2 passed`. T061 is accepted.

## Privacy contract test

`tests/cloud/package-privacy.test.ts` independently injects foreign records, private Storage keys, API keys, credentials, and payment data outside the export allowlist. It confirms those sentinels and forbidden key names never enter the ZIP. It also verifies an over-limit recovery input is rejected before archive parsing.
